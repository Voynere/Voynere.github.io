Очереди и кэш: RabbitMQ и Redis

16 августа 2026 · 1 мин чтения

symfony · redis · rabbitmq

Когда продукт выходит за рамки «страница + форма», одного PHP-процесса мало. Импорт прайсов, письма, вебхуки, пересчёты — всё это лучше уводить из HTTP-запроса.

В моём Symfony-контуре обычно так:

  • RabbitMQ — транспорт для Messenger: задачи живут в очереди, воркеры едят их отдельно от веба;
  • Redis — кэш, сессии, быстрые блокировки и счётчики, чтобы не бить базу на каждом шаге.

Правило простое: Redis — для «помнить быстро», RabbitMQ — для «сделать позже и надёжно». Если смешать роли, получится хрупкий зоопарк. Если разделить — деплой и отладка остаются предсказуемыми.
