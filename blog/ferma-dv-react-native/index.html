React Native: опыт Ferma DV

16 августа 2026 · 3 мин чтения

react-native · typescript · mobile · product

Ferma DV App — React Native‑клиент фермерского e‑commerce на ferma-dv.ru: каталог, корзина, checkout, зоны доставки, бонусы и push.

Стек на клиенте: React Native 0.81, TypeScript, React Navigation, Zustand, Firebase Messaging + Crashlytics, Keychain, turf для «точка в полигоне» зоны доставки.

BFF, а не телефон. Агрегация каталога (МойСклад + остатки WP + акции Kilbil + URL картинок) идёт на бэке: /mobile/catalog/products, /mobile/catalog/actions. В приложении — тонкий page‑cache в Zustand. Смена доставки вызывает clearProductsCache(): иначе на экране чужой склад и чужие цены.

Доставка и адрес. Адрес и тип доставки живут в AsyncStorage; UI не пускает в каталог «вслепую», пока зона не выбрана. Гео‑проверка через turf отсекает адреса вне полигона до того, как пользователь набьёт корзину.

Push и релизы. FCM через Firebase: на Android 13+ разрешение на уведомления отдельно от регистрации токена; refresh токена сразу уходит на сервер. Сборки — apk / aab / ipa скриптами в репо, плюс проверка signing перед релизом.

Вывод. Мобильный e‑commerce упирается в границу «телефон ↔ бэкенд». Если собирать каталог на устройстве — страдают FPS и батарея. Если отдать агрегацию BFF и оставить UI быстрым — продукт ощущается цельным, а баги склада не маскируются кэшем в кармане.
